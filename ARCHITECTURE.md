# Архитектура

Приложение собирается в статические файлы. Пользователь взаимодействует с пятью SPA-экранами через hash-навигацию. Маршруты совместимы с GitHub Pages в подкаталоге.

| Слой | Путь | Ответственность |
| --- | --- | --- |
| Интерфейс | `src/main.tsx`, `src/ui` | Навигация, ввод и проверка данных, таблицы, графики, формулы и сообщения |
| Финансовое ядро | `src/finance` | Типы, проверка активов, календарь UTC, проценты, агрегаты, сценарии |
| Данные | `src/data` | Начальные позиции, снимок условных курсов, валидация и сохранение LocalStorage |
| Аналитика | `src/analytics` | Оценка резерва и концентрации по эмитентам на основе введённых данных |

## Расчёты MVP

- Совокупный капитал равен сумме текущих стоимостей по снимку курсов. Резерв определяется классом «Денежный резерв». Работающий капитал — разность между совокупным капиталом и резервом. Ставка за ближайшие 12 месяцев — валовой доход за 12 месяцев, делённый на текущий капитал. Погашения исключены из дохода.
- Для календаря текущая сумма используется как база начисления и сумма погашения. Регулярный платёж равен ставке в долях, умноженной на базу и делённой на частоту. График привязан к стартовой дате, даты ограничены длиной месяца. Для неполного периода перед погашением процент начисляется пропорционально прошедшим дням от расчётного начала периода. Поддерживаемые классы выплат определяются типом позиции. Уже прошедшие даты исключены. Исторические позиции без стартовой даты используют дату расчёта. Позиции с истёкшим сроком остаются в учёте капитала до изменения пользователем.
- Для калькулятора чистый доход равен валовому доходу минус условный налог. Полные периоды капитализируются по ставке `r / n`, остаток начисляется простыми процентами. Индекс инфляции за срок равен `(1 + i)^(m/12)`. Чистый итоговый капитал делится на этот индекс и затем на первоначальный капитал, результат уменьшается на единицу.
- Сценарии конвертируют активы и их выплаты по курсу с применённым шоком. Изменение ключевой ставки смещает ставку накопительных счетов. Дюрация облигации приближённо равна остаточному сроку в годах (максимум 5), делённому на `1 + r`. При отсутствии даты погашения используется верхняя граница. Множитель цены — `max(0, 1 − дюрация × шок)`, где шок выражен в долях. Кредитный спред добавляется к шоку доходности корпоративных и юаневых облигаций. Погашенный номинал остаётся в капитале без дополнительных начислений.
- Реинвестируются процентные выплаты по ставке `max(0, 8% + шок ключевой ставки)` за остаток горизонта по ACT/365. Досрочное закрытие вклада в конце горизонта исключает весь доход по незавершённому вкладу. Изъятие применяется к каждому сценарию в конце горизонта и ограничено доступным капиталом.

MVP использует одну оценку вместо раздельного номинала, рыночной цены и НКД. Модель не учитывает индивидуальные даты купонов, амортизацию, комиссии и налоговые льготы. Для оценки общего изменения рыночной цены используются упрощённые шоки. Расчёты ведутся в числах двойной точности, округление применяется при отображении.

## Интеграции

- Снимки данных могут поступать из серверного адаптера с источником, временем обновления и признаком происхождения. Для MOEX ISS, Банка России, Росстата и документов эмитентов понадобятся отдельные адаптеры с проверкой единиц и дат.
- В FastAPI можно вынести API портфелей, снимков и налоговых правил. PostgreSQL или Supabase предоставят версионируемое хранение и пользовательский доступ. Для Python-ядра следует сохранить эталонные тестовые векторы TypeScript и сверять результаты.
- Будущий серверный аналитик передаёт OpenAI API только машиночитаемые результаты расчётов и их источники. Пользовательский интерфейс должен различать модельные выводы и детерминированные результаты. Сервер хранит ключи и отвечает за валидацию ответа. В MVP работают локальные аналитические правила.
